## 1. Что такое модель Sphera

Модель Sphera — это **один файл `.sm`** (обычно 1–10 МБ), внутри которого:

- **N-граммы** (статистика, какое слово идёт после какого)
- **Словарь** всех использованных слов
- **Определения** терминов (для запросов «что такое X»)

`.sm` — это сжатый бинарник, читать глазами его не нужно. Модель
собирается из **трёх текстовых файлов**, которые вы пишете сами:

| Файл | Что это | Сколько строк |
|---|---|---|
| `seeds.txt` | Список терминов (тем) | 50–5000 |
| `dialogs.txt` | Пары «вопрос → ответ» | 100–10000 |
| `config.json` | Параметры сборки | 1 файл |

После сборки вы получаете `my-model.sm`, который:
- запускается командой `sphera.exe run my-model`
- работает как HTTP API: `sphera.exe serve my-model`
- загружается на GitHub для других пользователей

- **Windows 10/11** (или Linux/Mac, если вы собрали `.py`-версию)
- `sphera.exe` (или `sphera.py` + Python 3.10+)
- Интернет (для скачивания определений из Википедии — опционально)

Создайте рабочую папку для модели:
my-model/

├── dialogs.txt
├── config.json
└── (сюда потом попадут определения и .sm)

## 3. Быстрый старт

Минимальный пример — модель, которая знает 5 терминов и 3 диалога.

### 3.1. `seeds.txt`

```txt
# Мои термины, по одному на строку. # = комментарий
физика
химия
биология
математика
астрономия
3.2. dialogs.txt
txt
<|user|>привет<|end|><|assistant|>привет!<|end|>
<|user|>как дела<|end|><|assistant|>хорошо, а у тебя?<|end|>
<|user|>пока<|end|><|assistant|>до встречи<|end|>
3.3. config.json
json
{
  "builder": {
    "models_dir": "./output",
    "data_dir": "./data",
    "memory_mb": 2048,
    "default_model": {
      "name": "my-model",
      "data_file": "definitions.txt",
      "ngram_order": 4,
      "min_freq": 3,
      "target_mb": 100,
      "context_tokens": 1024
    }
  }
}
3.4. Сборка
bat
REM 1. Скачать определения (нужен интернет)
sphera.exe download-wiki --seeds seeds.txt --out data\definitions.txt

REM 2. Собрать модель
sphera.exe create my-model --seeds seeds.txt --dialogs dialogs.txt --config config.json

REM 3. Запустить
sphera.exe run my-model
Готово. В папке output\ появится my-model.sm.

4. Формат файлов
4.1. seeds.txt — термины
Обычный текстовый файл, один термин на строку.

text
# Науки
физика
химия
биология

# Животные
собака
кошка
лошадь
Правила:

Строка # ... — комментарий, игнорируется

Пустые строки — игнорируются

Дубликаты — автоматически удаляются

Регистр: лучше нижний (физика, а не Физика)

Не используйте ударения (го́тфрид) — Википедия не найдёт

Не используйте смесь латиницы и кириллицы (мichael) — тоже не найдёт

Что попадёт в модель: для каждого термина из списка Sphera
скачает определение из Википедии и добавит как пару
«что такое X» → определение. Если для термина есть статья — она
войдёт в модель, если нет — термин будет пропущен с пометкой failed.

Сколько терминов нужно:

Терминов	Что получится
10–50	Демо, знает 10–50 определений
100–500	Мини-справочник по одной теме
1000–3000	Базовый энциклопедический охват
5000+	Широкий охват, но дольше качать (30–60 мин)
4.2. dialogs.txt — диалоги
Файл с парами «вопрос → ответ» в специальном формате с маркерами.
Каждая пара — одна строка (или две строки, но лучше одна).

Формат:

text
<|user|>ВОПРОС<|end|><|assistant|>ОТВЕТ<|end|>
Примеры:

txt
<|user|>привет<|end|><|assistant|>привет!<|end|>
<|user|>как дела<|end|><|assistant|>хорошо, а у тебя?<|end|>
<|user|>что делаешь<|end|><|assistant|>отвечаю на вопросы<|end|>
<|user|>спасибо<|end|><|assistant|>пожалуйста<|end|>
<|user|>пока<|end|><|assistant|>до встречи<|end|>
Несколько ответов на один вопрос — просто добавьте несколько строк:

txt
<|user|>привет<|end|><|assistant|>привет!<|end|>
<|user|>привет<|end|><|assistant|>здравствуй!<|end|>
<|user|>привет<|end|><|assistant|>привет, как ты?<|end|>
<|user|>привет<|end|><|assistant|>рад тебя видеть<|end|>
При ответе модель будет выбирать случайный вариант из доступных.
Чем больше вариантов — тем живее звучит.

Правила:

Строка # ... — комментарий

Кавычки «» или "" — можно, они сохранятся в ответе

Точка в конце ответа — желательна (модель ориентируется на неё)

Регистр важен для первого слова: Привет и привет — разные ключи

Символ | внутри <|user|> и <|assistant|> — не использовать в тексте

Сколько пар нужно:

Пар	Что получится
20–50	Демо, только базовые реплики
100–300	Живой чат на бытовые темы
500–2000	Хорошее покрытие повседневных тем
5000+	Модель редко «не знает» что ответить
Советы:

Пишите варианты формулировок: «как дела», «как ты», «как жизнь»

Пишите опечатки: «превет», «кагдила» — Sphera их распознает

Пишите сокращения: «спс», «чё как» — тоже работают

Для приветствий — 5–10 разных ответов

Для «спасибо» — 3–5 вариантов

Для редких тем — 1–2 варианта

4.3. config.json — параметры
Управляет тем, как собирается модель.

json
{
  "builder": {
    "models_dir": "./output",
    "data_dir": "./data",
    "memory_mb": 2048,
    "default_model": {
      "name": "my-model",
      "data_file": "definitions.txt",
      "ngram_order": 4,
      "min_freq": 3,
      "target_mb": 100,
      "context_tokens": 1024
    }
  }
}
Что означает каждый параметр:

Параметр	По умолчанию	Что делает	Рекомендация
models_dir	./output	Куда сохранять .sm	Оставьте
data_dir	./data	Где лежат definitions.txt	Оставьте
memory_mb	2048	Лимит памяти при сборке	1024 для слабых ПК
name	—	Имя модели	Ваше название
data_file	definitions.txt	Файл определений	Оставьте
ngram_order	4	Длина контекста (3–6)	4 для чата, 3 для определений
min_freq	3	Мин. частота слова (2–5)	3 баланс, 2 больше слов
target_mb	100	Целевой размер модели	50–500 в зависимости от данных
context_tokens	1024	Контекст в токенах	Оставьте
Как выбирать ngram_order:

3 — модель «знает» отдельные слова, плохо строит фразы

4 — баланс, модель строит короткие фразы ✅ рекомендуется

5 — лучше связность, но нужно больше данных

6 — почти всегда «не знаю», слишком специфично

Правило: ngram_order не должен превышать среднюю длину
ответа в словах. Если ответы короткие (привет, пока) — берите
3, если длинные (1–2 предложения) — 4.

Как выбирать target_mb:

Пар	target_mb
100	10
500	30
2000	80
5000	200
20000	500
Если поставить слишком много — модель будет «пухнуть» от редких
n-грамм и плохо отвечать. Если мало — обрежется важное.

5. Сборка модели
5.1. Получить определения (опционально)
Если у вас есть seeds.txt, скачайте определения из Википедии:

bat
sphera.exe download-wiki --seeds seeds.txt --out data\definitions.txt
Что происходит:

Для каждого термина идёт запрос к ru.wikipedia.org

Берётся первое предложение из введения

Очищается от вики-разметки

Сохраняется как пара «что такое X» → определение

Сколько займёт: ~1 секунда на термин + пауза 1.5 сек
(защита от rate limit). 1000 терминов ≈ 25 минут.

Если не хотите качать — просто создайте пустой data\definitions.txt
или пропустите этот шаг. Модель будет работать только на диалогах.

5.2. Собрать .sm
bat
sphera.exe create my-model --seeds seeds.txt --dialogs dialogs.txt --config config.json
Что происходит:

Читаются seeds.txt и dialogs.txt

Читаются data\definitions.txt (если есть)

Строится словарь

Считаются n-граммы

Применяется прунинг (обрезка редких контекстов)

Сохраняется output\my-model.sm

Что увидите в консоли:

text
[build] прочитано пар: +3924 (data\definitions.txt)
[build] прочитано пар: +962  (dialogs.txt)
[build] модель 'my-model': 4886 пар, order=4
[convert] собираю forward из pairs (со спецтокенами)...
  1-gram: 1 контекстов
  2-gram: 17,384 контекстов
  3-gram: 39,441 контекстов
  4-gram: 49,886 контекстов
[check] (<|assistant|>,) в forward[2]: ДА
[save] output\my-model.sm (1.84 MB)
[done] модель my-model сохранена
Ключевая строка: [check] (<|assistant|>,) в forward[2]: ДА.
Если там НЕТ — что-то сломано, модель будет отвечать мусором.
Обычно это значит, что dialogs.txt пуст или все пары битые.

5.3. Параметры командной строки
bat
sphera.exe create ИМЯ ^
    --seeds seeds.txt ^
    --dialogs dialogs.txt ^
    --config config.json ^
    --definitions data\definitions.txt ^
    --order 4 ^
    --target-mb 100
Все флаги опциональны — что не указали, возьмётся из config.json.

8. Продвинутое
8.1. Расширение определений (парафразы)
Одна пара «что такое физика» → определение — это одна n-грамма.
Модель не поймёт «расскажи о физике» — там другой контекст.

Решение: создайте больше формулировок для каждого термина.

Создайте expand.py:

python
import re, sys

patterns = [
    'что такое {t}',
    'расскажи о {t}',
    'расскажи про {t}',
    'объясни {t}',
    'что значит {t}',
    'определение {t}',
    'что ты знаешь о {t}',
    'дай определение {t}',
]

def main(src, dst):
    with open(src, encoding='utf-8') as f:
        text = f.read()
    pat = re.compile(
        r'<\|user\|>что\s+такое\s+(.+?)<\|end\|>'
        r'<\|assistant\|>(.+?)<\|end\|>'
    )
    pairs = pat.findall(text)
    with open(dst, 'w', encoding='utf-8') as f:
        for term, answer in pairs:
            term = term.strip()
            for p in patterns:
                f.write(f'<|user|>{p.format(t=term)}<|end|>'
                        f'<|assistant|>{answer}<|end|>\n')

main(sys.argv[1], sys.argv[2])
Запуск:

bat
python expand.py data\definitions.txt data\definitions_expanded.txt
Теперь вместо 1000 пар получите 8000. Модель будет отвечать
на «расскажи о X», «объясни X», «что значит X» — а не только на
«что такое X».

Важно: после расширения удалите definitions.txt из папки
data\ или переименуйте, чтобы не попало в модель дважды.

8.2. Разные модели под разные темы
Соберите несколько отдельных моделей:

chat.sm — только диалоги (бытовая болтовня)

science.sm — только определения наук

legal.sm — юридические термины

games.sm — игровая тематика

Каждая будет ~1 МБ и отвечать точно по теме. В sphera run можно
запускать любую. А в sphera serve — поднимать несколько на разных
портах:

bat
start sphera.exe serve chat --port 11434
start sphera.exe serve science --port 11435
8.3. Ускорение ответов
Если модель тормозит:

Уменьшите ngram_order до 3 (меньше контекстов)

Уменьшите target_mb до 50 (сильнее прунинг)

Увеличьте min_freq до 4–5 (меньше слов в словаре)

8.4. Улучшение качества диалогов
Добавьте варианты одной фразы — привет / здравствуй / хай

Добавьте опечатки — превет / привте / спс

Избегайте длинных ответов (1–2 предложения — оптимум)

Ставьте точку в конце ответа (модель на неё ориентируется)

Не пишите ответы короче 2 слов (кроме приветствий)
